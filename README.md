# dsh-role-play

轻量角色扮演聊天插件，给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）用。

**一个可随意设置角色卡的轻量角色扮演，安装即用，简单易上手。** 支持长／中／短三种对话模式、一键强化情感张力、成人向描写开关、自带角色扮演专用默认模型、自动记忆与角色状态栏，还能让角色感知当前真实的时间。

> **自带专用默认模型，不动你的全局设置。** 不选模型时，插件用自己挑的角色扮演模型，而不是「设置 → 模型」里的全局默认——那个是给写代码、查资料那些对话用的，换掉会波及本插件之外的用途。两者互不影响，你手动选过之后则以你的选择为准。

没有文件导入，没有外部依赖，角色卡和聊天记录都存在浏览器本地。

> 与 `dsh-tavern` 的区别：那个是全功能版（世界书、预设、记忆、关系、变量表、状态栏等）；这个刻意做小，一个视图、几个字段，装完就能用。

> **扩展玩法**：装上配套的 [多角色故事](https://github.com/zhengwuyu957/dsh-role-play-story)（`dsh-role-play-story`）后，视图栏会多出一个「多角色故事」标签页，可以让你这里的角色们进入同一个场景，彼此对话、互相吃醋、争抢、冷战，也和你互动。那个插件从本插件读取角色卡，所以必须先装这一个。

## 功能

**角色卡**
- 应用内新建 / 编辑：名字、角色图（导入本地 PNG）、人设、情景、开场白
- 两个可选的剧情字段：**角色想要什么**（推动剧情的欲望）、**角色在防备什么**（心理防线）。留空由模型按人设推断
- 角色图等比缩放到 256px 存成圆形头像

**对话**
- 每个角色独立保存聊天记录（浏览器 `localStorage`）
- 流式回复，实时看到角色在说
- 顶栏**模型选择器**：列出当前部署注册的所有 provider / 模型，选择会记住；不选则使用**角色扮演专用默认模型**（见下）
  - 插件自带一个角色扮演优先模型，与「设置 → 模型」里的全局默认**互不影响**——全局默认是给写代码、查资料那些对话选的，换掉它会波及本插件之外的用途
  - 优先模型只在本机可选列表里确实存在时才生效；换机器、换订阅、模型下架时自动回落到全局默认，下拉框不会选中一个不存在的项
  - 你手动选过一次之后，就完全以你的选择为准，优先模型不再参与
- 回车发送，Shift+回车换行，中文输入法组词时不会误发

**回复操作**
- 每条角色回复下方有胶囊：**继续说**（让角色顺着自己的情绪往下讲，适合不知道怎么接的时候）、**重写**（丢掉这条，用同样上下文重新生成）
- 悬停任意消息出现 **↩**：回溯到那一轮，删掉该条及其之后的内容
- 顶栏「从开场白开始」：一键回到开头
- 输入框右上方胶囊：滚到中间显示「回到顶部」，滚到顶部变「回到当前」（跳回最近一轮），停在底部时隐藏

**对话模式**
- 输入框左上方的「对话模式」胶囊打开设置面板
- 三种长度：**长对话**（200–500 字）／**适中**（60–180 字）／**简短**（15–50 字），选择会记住
- **加强（张力MAX）**：一键把情感张力拉满，强化危险性、攻击性、占有欲和关系拉扯。它只放大强度，不放大篇幅——和长度模式可以同时生效

**成人向描写（默认关闭）**
- 输入框左上方第六个胶囊「**成人向**」，点开可以开启／关闭
- 开启后，剧情走到成人内容时会写得直白、具体、缓慢，不再含蓄带过
- 提示词里给了具体的器官／行为本名词表和身体状态清单，并明确点掉了「幽径／蜜液／那一处」这类会被模型当替代词用的委婉说法——只说「要直白」实测不够，模型会理解成「不加修饰」然后继续写笼统的句子
- **指代你用「你」，指代角色用「我」或省略主语**，不允许把自己写成站着旁观的第三者
- 只在剧情真正进入成人内容时生效，日常场景照常叙述——不会把普通对话也写成情色
- **只允许成年角色之间**：角色卡没写年龄时按成年处理；出现未成年角色、或试图把世界观年龄标准调到 18 岁以下的，一律停止推进成人内容
- **关闭时系统提示词与未加此功能时逐字相同**（有自动化测试逐字比对）

> ⚠ **写不写得直白，主要看模型。** 同一个插件、同一份提示词，不同模型的差距是数量级的（实测每轮显式词 6.00 对 0.00）。所以 1.7.0 起插件自带一个角色扮演优先模型，不选模型时默认用它；如果仍然含蓄，**先换模型**（右上角下拉框），而不是反复改角色卡。设置面板里也会直接提示这一点。

**自动记忆（滚动摘要）**
- 聊得久了，未压缩的消息超过 24 条时，最早的一批会自动压缩成一段「前情提要」
- 之后的每次对话只发送「前情提要 + 最近的消息」，上下文不会无限增长，角色也不会失忆
- 摘要会累积：多次压缩会保留之前的提要一起再压，越早期的事越浓缩
- 输入框左上方有独立的「**记忆**」胶囊，点开可以查看压缩进度、读取前情提要全文、手动清空
- 回溯到某一轮或从开场白重开时，记忆会同步回退／清空

**角色状态栏**
- 输入框左上方第三个胶囊「**状态**」，点开查看角色此刻的**情绪／场景／对你的态度**
- 每轮对话后自动分析刷新，也可以手动「重新评估」
- 状态独立保存，可以「清空状态」

**时间感知**
- 输入框左上方第五个胶囊「**时间**」，默认开启，显示此刻的真实时间，例如 `2026年11月13日 周五 23:40（深夜·秋季）`
- 开启后，每轮对话都会把当前时间告诉角色：它知道现在几点、白天黑夜、星期几、什么季节
- 于是它会问「这么晚怎么还不睡」、饭点提吃饭、深夜语气犯困、冬天写窗外的冷——细节自己就对上了
- 时间在**每次发送时现算**，所以聊到半夜，角色也跟着走到半夜
- 可以随时关掉。关闭后不发送任何时间信息，**提示词与未加此功能时逐字一致**
- 不读系统日历、不联网：只用浏览器本地时区，和你的系统时钟一致

**对你的认知**
- 输入框左上方第四个胶囊「**对你的认知**」，点开设置这个角色眼里的你：**姓名、性别、性格**
- **每个角色独立保存**——同一个你，在不同角色眼里的样子可以不一样
- 填了姓名，角色就会用这个名字称呼你；填了性格，角色会按这个印象对待你
- **性别留空时跟随角色卡的性别**（角色是女，就默认你是女）；单独填了就按填的来
- 认知只影响这一个角色，不会串到别的角色

**角色卡性别**
- 角色卡上的「性别」指的是**这个角色自己的性别**，不是你的
- 填了之后，叙述这个角色时会用正确的「他」或「她」，不会再搞混
- 在「多角色故事」里，你扮演的那个角色的性别，就是你的性别

**角色卡生成**
- 左侧栏「+ 新建角色」点开后有两个入口：
  - **自定义**：和原来一样，手动填写全部字段
  - **关键词生成**：输入几个关键词（如「雨夜、外科医生、嘴硬心软」），AI 生成完整角色卡（名字、头像、性别、人设、情景、开场白、欲望、防线），生成后会打开编辑器供你修改
    - 模型输出的 JSON 常常是坏的（角色设定里引用台词时，引号基本不会转义），所以解析器做了四级兜底：原文 → 修引号 → 补括号 → 按字段掏。被截断、带代码块标记、前后有废话、中文键名都能救回来
    - 真的失败时会**显示具体原因**（接口报错原文／模型返回空／无法解析并附上开头／缺名字并列出了字段），而不是一句笼统的「生成失败」

## 扩展玩法：多角色故事

配套插件 [dsh-role-play-story](https://github.com/zhengwuyu957/dsh-role-play-story) 会复用这里的角色卡和模型配置，提供**多角色同场**的故事模式：

- 几个角色进入同一个场景，**角色之间会直接交流**——接话、反驳、试探、争抢、冷战，不再各自只对你说话
- 两种节奏：**轮流**（按顺序开口，秩序感强）／**自由**（谁情绪最强谁先说，可以有打断抢话）
- **自动续演**：每轮结束自动往下走，看他们自己演
- 新建故事支持**情节生成**：描述想要的剧情，AI 会从现有角色里自动挑人并生成背景，生成后可以改

安装顺序：先装本插件，再装那个。那个插件从本插件读取数据，缺失时会显示提示页而不是崩溃。

## 安装

需要 DSH 已装好。

```sh
git clone https://github.com/zhengwuyu957/dsh-role-play.git
```

然后在 DSH 里用 Plugin Manager 安装这个目录：

```js
pluginManager.install_bundle({ action: 'install_bundle', target: '<仓库绝对路径>' })
```

装完 **完全退出 DSH 再打开**（Host 侧代码要重启才加载；之后改 `client.js` 通常刷新页面即可）。

进入任意会话，在视图栏选 **「角色扮演」**。

### Windows 跨盘符注意

若仓库与 DSH profile 不在同一个磁盘分区，pnpm 会生成失效的相对符号链接，表现为安装成功但插件解析不到。把 profile 里的链接换成 junction：

```powershell
$link = "$env:DSH_PROFILE_DIR\node_modules\dsh-role-play"
(Get-Item $link).Delete()
New-Item -ItemType Junction -Path $link -Value "<仓库绝对路径>"
```

## 使用

1. 点「+ 新建角色」，填名字、导一张图、写人设和开场白
2. 顶栏选模型
3. 开始聊

「角色想要什么 / 角色在防备什么」是可选的，但填了之后剧情张力会明显更好——模型有了明确的动机和阻力，而不是泛泛地友善。

## 结构

```
index.js            Host 半部：注册 /rp-chat/api/* 路由，转发到 DSH 的 llm 服务做流式补全
client.js           Client 半部：conversation.view 里的「角色扮演」视图
cordis.patch.yml    Bundle patch：插入 roleplay-chat 这一行插件
locale/en.json      插件管理页的英文标题与描述
locale/zh.json      中文标题与描述
icon.svg            插件图标
```

### 接口

| 路由 | 说明 |
|---|---|
| `GET /rp-chat/api/model` | 返回模型清单与默认选择：`{ default, deploymentDefault, preferredAvailable, options: [{ provider, model, name? }] }`。`default` 在优先模型可用时是它，否则等于 `deploymentDefault`（全局默认） |
| `GET /rp-chat/api/health` | 只读自检：`{ version, policy: { enabled, available, active, … } }`。用于确认插件版本与可选的内容策略桥接状态 |
| `POST /rp-chat/api/chat` | 流式补全。请求体 `{ system, messages: [{ role, text }], provider?, model?, temperature?, maxTokens? }`，SSE 响应：`{"type":"delta","text":"…"}`、`{"type":"done"}`、`{"type":"error","message":"…"}` |

路由有同源校验（拒绝 `Origin` 与 `Host` 不符的请求）。

## 数据存放

所有数据都存在浏览器 `localStorage`，插件本身**不写任何文件、不碰你的硬盘**。键名前缀 `rpChat.`。

| 键 | 存什么 |
|---|---|
| `rpChat.characters.v1` | 角色卡（含头像与角色图 data URL、性别） |
| `rpChat.chats.v1` | 完整聊天记录（按角色分组，原文逐条保存） |
| `rpChat.memory.v1` | **角色的滚动记忆**：按角色分组的前情提要，以及已压缩到第几条的游标 |
| `rpChat.status.v1` | 角色状态栏（情绪／场景／对你的态度） |
| `rpChat.userProfile.v1` | 「对你的认知」：这个角色眼里的你的姓名、性别、性格 |
| `rpChat.timeAware.v1` | 时间感知开关（`true` / `false`，默认 `true`） |
| `rpChat.adult.v1` | 成人向描写开关（`true` / `false`，默认 `false`） |
| `rpChat.selected.v1`、`rpChat.model.v1`、`rpChat.dialogueMode.v1`、`rpChat.maxTension.v1` | 当前角色、模型、对话模式、张力开关 |

关于记忆的两点：

- **记忆和聊天记录是两份东西**。聊天原文完整存在 `chats`，`memory` 里只有压缩后的提要。删掉记忆不会删掉聊天记录，只是让角色「忘掉前情」。
- **记忆保的是事实和关系，不是原话**。早期对话被压缩成摘要后，具体措辞会丢失。需要长期记住的设定，写进角色卡的「人设」或「情景」更可靠。

清除浏览器数据、换一个浏览器、或用无痕模式打开，都会让这些消失——它们不会跟着 DSH 的配置文件走。

## 回复质量机制

角色回复的「人味」不只靠提示词，下面这几件事一起起作用：

**抗历史污染**
模型会模仿自己前几轮写下的腔调。一旦连续出现「（看着你）」「（没说话）」这类空壳回复，后面就会越写越短、越写越干。插件会在发送前从末尾回溯连续干瘪的回复，保留最新一条作为上下文承接点，给更早的那些追加退稿标记，打断这种模仿。

只作用于发给模型的副本——**聊天记录、前情提要、浏览器存储都不受影响**。

**回避场景的推进**
你不接话、躲开、岔开话题时，角色不会被带着一起安静，而是用行动推进：跟过去、堵在门口、把东西摆到你面前。

**动态干瘪提醒**
最近几条回复如果普遍偏短，会在本轮追加一次提醒。短模式自动跳过（短模式本来就该写短）。

**按题材分型**
病娇／偏执型走「温柔地做可怕的事」——日常话的外壳 + 控制欲的内核；甜宠／日常型甜在具体的事，不在形容词。

**时间感知的边界**
时间块是加在系统提示词里的独立一段，**不改动任何一条原有规则**。它只交代「现在是什么时候」，并要求角色别生硬报时。关掉开关后整段消失，提示词与旧版逐字相同——原有的语气、长度、防跑偏设定全都不受影响。

**成人向的边界**
成人向那一段也是独立成段、开关控制、关掉即整段消失。它和张力 MAX 分工明确：张力管**情绪的强度**，成人向管**描写的密度**，所以和长／中／短模式可以同时生效。段内写死了年龄边界（成年角色之间、18 岁不外扩），遇到越界设定的场景直接停止推进而不改写人设。

这一段还有一条**优先声明**：当它与前面【文风】【禁止八股】里「动作要简省」「不要拆成独立段落」「一个动作胜过三句形容」发生冲突时，成人场景以本段为准。没有这一条，那些为了治 AI 腔而设的克制规则会把成人场景直接压平——这也是之前「不够细」的原因之一。

**主控的人称（1.5.3 修）**
格式要求第 2.1 条原本写着「指代用户一律用『你』」，但紧接着的 2.2 条又写「需要指代用户时用『她』相关的说法」——**两条互相打架**，模型就随机漂移，写出「（低下去在她颈窝贴了一下）」这种把用户写成第三方的句子。

2.2 现在只负责「身体特征按什么性别写才不出错」，不再给任何「可以用第三称指代用户」的许可。A/B 实测（4 模型 × 3 轮）括号内漂移从 **7 次降到 2 次**。

**配角视角**
剧情里出现第三个角色时，最容易被写坏的是**视角归属**——镜头从你扮演的角色身上漂到刚出场的人身上，读起来就是「不明所以的话和不相干的动作」。规则里写死了：

- 括号里不许用配角作主语（不写「（沈池应了一声往外走）」，要写成「（看见沈池应了一声往外走）」）
- 配角只能作为角色的观察对象出现，不写他的心理、动机、主观感受
- 一轮里配角只做一件事，说完焦点立刻回到角色身上
- 台词归属：只有两个人时台词直接写；一旦有第三个角色开口，用（角色名）标出说话人

这一段明确写着「只在有别人出场时才用，没有别人在场时完全不适用」，且「不改变篇幅」——两人对话的回复质量与长度都不受影响。

## 已知限制

- 聊天记录只在浏览器本地，不参与 DSH 的会话日志与 fork / replay
- 角色图以 PNG 存进 `localStorage`，图多时占配额（浏览器通常限 5～10 MB）
- 界面文案固定中文；仅插件管理页的标题 / 描述是双语
- 时间感知取的是浏览器本地时区与系统时钟；系统时间不对，角色看到的时间也不对（不联网校时）
- 依赖宿主的 `llm` 与 `webServer` 服务，缺任意一个都不会激活
- 抗污染与干瘪提醒能明显改善质量，但不保证每次都达到模式的理想篇幅
- 成人向开关本身不做内容审核：它只负责「写不写得细」，是否写、写到哪一步仍由剧情和你自己的输入决定
